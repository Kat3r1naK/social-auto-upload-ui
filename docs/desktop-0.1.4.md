## 实现

1. 安装包继续排除未使用的 headless shell，新增语言筛选和两份驱动 node.exe 的排除规则。两套匹配各自驱动的完整 Chromium 保留。Python 子进程通过 PLAYWRIGHT_NODEJS_PATH 使用 Electron 内置 Node，文章渲染继续使用同一运行时。
2. 准备运行时时预生成 17 个平台、25 种内容组合的参数 JSON。启动时校验 worker 可执行文件 SHA-256 和字段结构；匹配时直接读取参数，不启动 Python。元数据缺失、损坏或不匹配时回退到受并发限制的 worker。
3. 上传、账号登录／检查、参数读取共享一个全局并发预算。默认最多两项；设置中的“省内存模式”改为一项并持久化。降低上限后已有任务继续完成，等待中的工作按顺序启动。退出时取消未启动的操作。
4. 任务列表使用 SQLite 分页及筛选，只返回摘要，每页 25 条。任务详情按主键获取完整正文。计数单独查询，导航与工作台不依赖当前页数量。素材索引不携带文章正文，在预览或使用素材时读取详情。后续刷新省略未变化的完整工作区。
5. 导出在主进程逐条读取并写入临时文件，完成后替换目标文件，包含所有符合筛选条件的完整任务，避免只导出当前页或丢失正文。
6. 关闭窗口进入托盘，一分钟后请求编辑器保存草稿，并等待工作区写入成功，再销毁窗口。保存失败时保留窗口。队列与托盘留在主进程；再次打开重建窗口，恢复路由、窗口位置、草稿和主题。隐藏期间暂停向渲染层推送刷新，打开时重新读取状态。
7. 重启恢复只查询运行中及错过时间的任务；删除账号和素材时使用数据库条件查询；导入素材按文件路径查询，减少读取整个历史／正文数组。

合成 1000 条历史任务、每条约 8K 字符正文的基准中，完整历史数组为 24,708,576 字节，第一页摘要和计数为 2,546 字节。这是该合成样本的列表传输大小，不是整体内存降幅。复现：`npm run build:desktop` 后运行 `node desktop-dist/desktop/scripts/benchmark.js`。

## 验证

- `npm run build`：严格 Vue／TypeScript 检查和生产构建通过。
- `npm test`：8 项前端测试、18 项桌面测试通过。覆盖持久化、队列、中断、参数生成／回退、分页／搜索／计数、完整导出、全局限流、退出队列清理及保存失败不释放窗口。
- 真实 worker 的 17 平台、25 种内容组合参数加载通过，未执行平台发布。
- `check-bundle` 对最终 0.1.4 包清空 PATH 验证 SQLite、文章渲染、biliup；确认只带两个语言包、没有独立驱动 Node 和 headless shell，并实际使用 Electron Node 启动两套完整 Chromium，离线渲染页面成功。
- 最终 app.asar 内五个桌面主文件和全部前端产物共 47 份文件逐项 SHA-256 与当前构建一致，版本 0.1.4，测试文件未入包。
- 隔离窗口回归通过任务翻页、完整详情、素材正文按需读取、内存模式持久化，以及真实一分钟后的界面释放、窗口重建、路由和完整草稿恢复。
- 最终打包客户端实际界面显示版本 0.1.4；25 种平台参数与预生成文件逐项一致；省内存模式的界面勾选和后端上限同步验证通过。
