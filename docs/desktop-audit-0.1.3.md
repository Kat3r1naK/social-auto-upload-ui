## 已落地的样式与交互优化

- 保留现有深紫色设计、导航和页面布局。素材与任务加入分页，避免一页持续增长。
- 设置页辅助文字由 12px 增至 13px；长数据目录允许换行，操作按钮不被文字挤压。
- 为滚动内容保留滚动条空间，减少内容数量变化时的横向跳动。
- “导出备份”改为“导出内容”，明确 JSON 只包含草稿和任务记录，素材文件与账号会话需要单独备份。
- 观察到搜索框焦点、内容预览、任务弹窗和主题切换正常。未宣称通过完整 WCAG、屏幕阅读器或最小窗口尺寸认证。

## 内存、CPU 和磁盘优化

| 指标 | 优化前 | 0.1.3 | 说明 |
| --- | ---: | ---: | --- |
| Windows 安装程序 | 723.71 MiB | 约 547.00 MiB | 对比本地 0.1.2 安装程序，约减少 24.4% |
| 解包安装目录 | 2246.60 MiB | 约 1702.92 MiB | 约减少 543.68 MiB |
| Element Plus / 图标 JS 块 | 1097.51 kB | 957.39 kB | 注册实际使用的组件、图标，减少约 12.8%；CSS 仍沿用完整样式表 |
| 单次历史任务查找 | 111.802 ms | 0.117 ms | 本地合成数据，30 次平均 |
| 单次待执行队列读取 | 104.971 ms | 0.096 ms | 同一数据库，30 次平均 |

性能样本为 1000 条历史任务（每条约 8K 字符正文）和 1 条到期待执行任务；复跑会因磁盘缓存及系统负载变化。专项查询提速不等于整体客户端提速，也不能推算整机内存降幅。可运行 `npm run build:desktop` 后执行 `node desktop-dist/desktop/scripts/benchmark.js` 复现。

具体措施：

1. 用任务主键查询替代读取整份历史后查找；调度器利用现有索引只读取已启用且到期的任务。媒体协议按素材主键查找，避免每次请求解析整个素材库。
2. 桌面任务仍由主进程队列持有。渲染层的工作区保存不再监听并重复序列化真实任务历史；保留草稿和主题持久化。
3. 合并并发快照请求；刷新期间到达的新通知会触发一次后续读取，避免旧数据覆盖新状态。错误显示为离线并保留已加载数据；释放工作区时取消事件订阅。
4. 相同平台参数请求共用一个 worker；不同平台参数串行读取，避免选择多个平台时同时拉起多份 Python 运行时。成功结果继续缓存，失败可以重试。
5. 素材图片懒加载、异步解码；网格视频不预读元数据，打开预览时再加载。每页最多 24 个素材节点、25 个任务节点。
6. worker 退出并读取结果后，清理本次操作的 request/result/临时验证码传输文件，空任务目录随之移除。生成的文章源文件和诊断材料保留，原始素材不受影响。
7. 打包排除两份未使用的 headless shell、浏览器链接元数据、桌面测试和构建脚本；运行时准备改为 `--no-shell`。两个驱动各自匹配的完整 Chromium 均保留。

`--no-shell` 是 Playwright 支持的安装选项；完整 Chromium 可以执行新的无头模式。不同版本驱动与浏览器的兼容性需要保留匹配关系，不能简单合并成一个任意版本。[Playwright 浏览器说明](https://playwright.dev/python/docs/browsers)、[BrowserType 文档](https://playwright.dev/python/docs/api/class-browsertype)。减少不必要的依赖加载和测量具体热点也符合 [Electron 性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)。

本轮减少的是**新版安装后的占用和后续运行时开销**。没有清理已安装 0.1.1 的目录，也没有删除工作区中的历史发行包。检查时 `release/` 已有约 11.61 GiB 历史产物，另有约 389.8 MiB worker 构建副本和 30.8 MiB 构建缓存；这些属于后续可按需清理的开发产物，不应与用户素材混为一谈。此次交付还会新增一份 0.1.3 发行产物。

## 尚未完善的部分与建议顺序

| 优先级 | 缺口 | 证据与下一步 |
| --- | --- | --- |
| P1 | 全平台真实授权、发布及结果核验未完成 | 当前自动测试验证 17 平台、25 种内容组合的参数加载，不代表平台真实登录、上传、审核通过。应按常用平台逐一验收并记录结果。 |
| P1 | YouTube 在干净电脑可能依赖已安装的 Chrome | `uploader/youtube_uploader/main.py` 登录、检查和上传使用 `channel="chrome"`，没有像其他桌面适配一样指定随包可执行路径。需要补齐路径适配和无系统 Chrome 的安装环境验证。此次未改上传核心。 |
| P1 | 账号检查失败原因过于粗略 | `desktop/service.ts` 将检查的 `ok=false` 归入过期；网络异常与会话失效应由 worker 返回不同结果类型，避免错误引导重新授权。 |
| P2 | 备份没有恢复闭环 | 设置只导出草稿和任务；缺少导入、迁移校验、素材路径重绑定、账号会话恢复流程。此次先纠正文案，后续应设计完整备份恢复。 |
| P2 | 历史数据仍全量进入快照 | 当前分页限制渲染节点；SQLite 到渲染层仍传完整任务/素材数组，正文也保留在内存。数据规模继续增加时，应增加数据库分页和按需详情接口。 |
| P2 | 实时诊断体验不足 | 任务详情事件主要在打开详情时读取；worker 日志未通过独立增量事件持续更新。建议任务日志单独订阅，避免用全量快照刷新日志。 |
| P2 | 缺少稳定的更新与安装验收流程 | 未配置自动更新和回滚流程；应补齐升级、卸载、重装以及干净 Windows 环境检查。 |
| P3 | 筛选状态和小字可继续改善 | 步骤 7 中任务页的搜索词被历史页沿用；建议分别保存筛选条件。个别辅助文字仍为 10–12px，后续应结合最小窗口尺寸检查对比度、键盘和缩放。 |
| P3 | 共享模型仍依赖前端目录 | `shared/desktop.ts`、`shared/platforms.ts` 与桌面服务引用前端类型文件。建议将领域模型统一放入 shared，前端用重导出保持兼容。 |

当前 Electron → 受限 preload/IPC → TypeScript 服务/SQLite → 独立 Python worker 的分层可以继续使用。本轮没有引入新的框架或常驻服务；后续优先补齐接口边界和结果类型，而不是整体重写。

本地定时依赖电脑和客户端保持运行；退出或休眠错过的任务不会自动补发。任务状态为“已提交”仍需要去平台核验公开/审核结果，这是当前明确的产品边界。

- `npm run build`：严格 Vue/TypeScript 检查和生产构建通过。

- `desktop/python/check_browsers.py`：在最终包浏览器目录中，Patchright 和 Playwright 都以完整 Chromium 的无头模式离线渲染页面成功；测试目录没有 headless shell。
- `check-bundle`：清空 PATH 后，打包 Electron 的 SQLite、文章渲染、两份 Chromium 路径及 biliup 可执行程序检查通过。
- `app.asar` 中五个主进程文件及全部前端生产文件共 47 份逐文件 SHA-256 与本次构建一致；版本为 0.1.3，测试代码未入包。
- 原生页面验证如上。没有操作真实账号登录或发布，没有进行全平台真实上传、完整辅助技术认证或干净 Windows 安装验收。
