# 0.1.2：本机工作区、账号授权与任务中断

日期：2026-11-14。

## 修正的行为

0.1.1 把桌面客户端首次启动的默认工作区设成了 `demo`。用户因此看到示例账号、示例素材，添加账号也只保存示例数据，没有触发真实登录。0.1.2 桌面端始终进入本机工作区；旧版保存的 `demo` 选择在启动时迁移为 `live`，真实账号、草稿、任务及主题保留。浏览器界面预览仍保留单独的示例模式。

账号管理的主入口和空状态现在显示“授权账号”，弹窗明确说明扫码、平台登录和本机会话保存方式。新增账号和编辑别名使用独立的操作意图；首次登录失败后仍可再次点击“授权登录”，复用原账号记录，不会误走只保存别名的分支。平台认证沿用上传核心的登录与 Cookie 会话流程，并非新增统一 OAuth 服务。

## 中断任务

- 执行中任务的列表行、详情弹窗都提供“中断任务”。尚未运行的任务继续使用原有取消操作。
- 确认后仅停止选中任务的 worker 和它启动的浏览器等子进程。Windows 使用完整系统路径调用 `taskkill /PID <该 worker 的 PID> /T /F`，不按全局进程名关闭浏览器。
- 同一任务的重复中断合并处理；进程树停止前保持账号占用，避免同账号下一条任务过早启动。中断完成后状态记为 `unknown`（结果待核验），并写入事件日志。迟到的成功结果不能覆盖中断状态。
- 系统停止失败或超时会明确报错，允许重试，不伪报取消成功。退出客户端也会等待正在进行的中断操作结束。
- 中断无法撤回平台已接收的内容，用户应先去创作者中心核验，再决定是否重发。其他账号的任务继续运行。

## 验证

- `npm run build`：严格 Vue/TypeScript 检查和生产构建通过。
- `npm test`：4 项前端工作区测试、10 项桌面测试通过；包括干净初始化、旧版模式迁移、数据库故障不显示示例账号、同账号锁、中断失败重试及真实 Windows 父子进程终止。worker 参数测试覆盖原有 17 平台的全部 25 个内容组合。
- 最后补充并发停止等待后，相关 9 项服务与进程测试再次通过。
- 原生窗口验收使用独立 `.local/account-interrupt-qa/profile`，其登录和发布 worker 被本地模拟进程替代，未访问或发布到社交平台。实际检查了默认空白本机工作区、授权入口、两次授权调用复用一个账号，以及从任务详情确认中断后刷新状态和日志。
- 中断后读取验收数据库及进程存活情况：选中任务为 `unknown`，它的子进程已退出；另一账号任务仍为 `running`，它的子进程仍存活。验收结束后已关闭这些独立模拟进程，未关闭用户安装的客户端。
- 打包后逐文件核对 `app.asar` 中的主进程、preload、服务、worker 管理器和全部前端生产文件；最终校验和见安装包旁的 `SHA256SUMS.txt`。
